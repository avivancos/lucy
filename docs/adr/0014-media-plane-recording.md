# ADR 0014 - Media-Plane Recording

## Status

Accepted

## Context

Lucy needs call recording, transcript replay, and recording playback in the
platform dashboard, but ADR 0004 and ADR 0011 keep audio frames out of Python.
The SDK can coordinate consent, blob identifiers, and telemetry, while the media
plane owns the socket and the actual audio bytes.

## Decision

Recordings are produced by the media plane and referenced through control-channel
events and telemetry. Python may request recording start or stop, mint blob upload
targets, validate upload completion metadata, and emit `audio_ref` telemetry, but
it never receives raw caller or agent audio frames.

Recording support is additive to the control-channel schema:

- The gateway advertises capabilities in `SessionStarted.features`.
- Python sends `recording.start` and `recording.stop` directives.
- The media gateway reports `recording.started`, `recording.uploaded`, and
  `recording.failed` events.
- Each uploaded asset records leg, duration, byte count, hash, container, and
  consent reference.
- The frozen `BlobStore.prepare_upload(blob_id)` ABI remains unchanged. Hosted
  adapters expose the additive `prepare_upload_with_context` extension for the
  privacy-safe session identity, leg, and consent reference needed to negotiate
  a tenant-scoped target; the coordinator detects that extension without
  breaking legacy stores. Both paths return only an opaque upload reference to
  the control channel.
- Trusted media-plane wiring resolves that opaque reference to one atomic
  `RecordingUploadTarget` containing the signed URL and all required headers.
- Hosted presign keeps Lucy's candidate `blob_id` as the canonical external
  join key while the platform derives a tenant-namespaced private object key.
  The platform verifies byte count and content type with storage `HEAD`; the
  gateway attests duration and SHA-256 because Python never reads audio.
  Completion is accepted only when the immutable platform response matches the
  gateway event and prepared context.
- Signed PUTs require exactly `content-type: audio/wav` and
  `if-none-match: *`; the gateway follows no redirects. Upload target origins
  are restricted by exact scheme, hostname, and port to the platform endpoint
  origin or the explicit typed allowlist,
  and signed targets are redacted from object representations and transport
  logs.
  Cancellation persists a platform tombstone and attempts immediate deletion.
  Because an issued single-PUT URL cannot be revoked, the platform repeats
  deletion after expiry to close late-upload races.

The default SDK behavior remains no recording. `RecordingSpec.enabled` is false
by default, recording obeys the existing `record_audio` observability kill switch,
and blob uploads are suppressed for unsampled sessions unless a card explicitly
documents a different policy. The open SDK ships the coordination protocol and a
local blob-store simulator; hosted retention, erasure, signed playback URLs, and
cross-tenant recording search are platform concerns under ADR 0010.
Hosted storage is fail-open from the call's perspective: unavailable presign,
completion, or abort suppresses recording and emits only a local warning/drop
count. An ambiguous transport failure after dispatch or an invalid `201`
response receives a best-effort compensating abort; an explicit non-`201`
response does not claim a reservation. Client close rejects new prepares,
cancels and drains in-flight presigns and completions, rejects late completion
responses, and aborts every resolved reservation before closing the transport.
The close operation is single-flight and shields cleanup so caller cancellation
cannot bypass reservation cleanup or credential zeroization.

## Consequences

- Platform dashboards can play recordings by dereferencing `audio_ref` and
  recording metadata, not by reading SDK-local audio bytes.
- Tests must prove the seam with deterministic WAV files generated by
  `LocalGatewaySimulator` and uploaded with the complete resolved target through
  real HTTP to a local blob server.
- Card 70 landed the recording messages and card 51 now includes them in the
  Rust/Python golden conformance fixtures.
- Consent lineage, retention, and erasure are explicit product surfaces, not
  implied side effects of storing audio.
- `RecordingSpec` and the bounded opaque-ref validation land before card 46's
  first public PyPI release, so no published `LucySpec` or recording control
  payload requires migration. After that release, both ABIs remain frozen and
  any incompatible shape change requires a SemVer major-version disposition.
